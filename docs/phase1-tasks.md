# 一期执行任务清单与 Stage Spec

日期：2026-11-10。状态：待实施。实施任务 **0/24 完成**；本文编写完成不计作任何实现或实机验收完成。

## 1. 目标、范围与完成定义

一期交付一台完整装配的 USB-C 有线样机及可安装的软件：20 键矩阵＋独立 2U 大键、方屏、旋钮、五向开关；Windows 11 上两个由 VS Code 扩展启动的原生 Claude Code CLI 会话能产生真实状态，设备显示选中会话，按大键回到该会话。用户在原终端自行确认，设备不自动授权、不自动提交。

一期包含 S0 软件可行性、S1 模块联调及完整有线整机交付。三模、语音、任意已有终端接管、WSL／SSH、其他 IDE、云服务、桌宠动画、RGB 和量产不在一期。三模与语音首发目标保留在技术 PRD，后续另开 Stage Spec。

交付并验收以下完整链路才能称为完成：

> 安装软件 → 扩展启动并绑定 A/B → 两会话真实等待操作 → 方屏正确显示与切换 → 大键回到屏上会话 → 人在原会话处理 → 状态解除或明确过期 → 下一项 → 拔插／重启后恢复。

文档只能规定闭环和阻断条件，不能预先保证硬件与 API 实测必然成功。任何关键门槛失败都保留未完成，修复并复测；不以“代码写完”代替交付。

## 5. 逐项任务

### 准备与软件核心

- [ ] **T01 — 固定开发环境与一期版本**（软件；依赖：无）
  - 动作：检查 Windows、原生 VS Code、Claude Code CLI；选定可安装的 .NET、Node、Pico SDK、编译器、CMake／Ninja 版本，记录下载来源和锁文件。创建上节目录与 `doctor.ps1`，用最小工程验证编译。
  - 交付：版本清单、环境诊断、最小上位机／扩展／固件构建记录；账号登录由你完成，密钥不写日志。
  - 验收：在你的电脑上能构建最小产物；下载／代理故障由开发者排查，不把尚未运行的脚本标为通过。

- [ ] **T02 — 获取同口径硬件报价与责任承诺**（你＋硬件；依赖：无）
  - 动作：发送硬件规范，比较两家报价；逐项确认料号、预焊接口、固件归属、首次点亮、完整装配、源文件、返修、加工最小数量与交期。
  - 交付：报价对照和实际采购候选表，确定预算上限与合作方。
  - 验收：没有“只交 PCBA 不管点亮”等责任空白；未确认预算不采购。报价含私人信息时仅保存脱敏摘要或本地引用。

- [ ] **T03 — 采集真实 Hook 事件并形成状态表**（软件＋你；依赖：T01）
  - 动作：用受控无破坏性任务分别触发等待权限、允许、手动拒绝、Esc、工具失败、正常完成及退出；另验证两个会话和同名项目。记录事件类型、时间、会话及工具关联键，不保存提示词和凭证。
  - 交付：脱敏样本、事件到 running／waiting／failed／completed／unknown／offline 的转换表，解除证据和过期策略。
  - 验收：等待和解除都有实际证据；`PermissionDenied` 不代替手动拒绝；不支持的等待类型明确列出。若核心权限等待无法稳定采集，停止开板，先修适配。

- [ ] **T04 — 实现扩展管理终端和窗口绑定**（软件；依赖：T01）
  - 动作：扩展提供“启动受管会话”命令，注入随机绑定 ID，维护窗口实例与 Terminal 对象；主动绑定前台 HWND 并校验进程及扩展焦点。退出、窗口重建、重载后旧绑定失效。
  - 交付：开发版扩展、命名管道注册／回执、绑定诊断界面或命令。
  - 验收：同窗口两终端和两窗口各能准确选择；重名不影响识别，失效句柄不跳其他窗口。先不接硬件。

- [ ] **T05 — 实现上位机队列与模拟设备入口**（软件；依赖：T03、T04）
  - 动作：实现有界 IPC、当前用户访问限制、Hook 短连接超时、扩展路由、队列去重、选择与过期；提供模拟屏和全局热键触发大键。焦点请求必须关联回执，确认前台窗口和终端后才算成功。
  - 交付：可运行 CLI、状态重放测试、模拟屏、错误反馈。Hook 上报失败时迅速返回，不改变 Agent 授权决定。
  - 验收：重复、乱序、无关工具完成不错误清除待办；上位机退出不阻塞 Claude；失效目标拒绝执行；无按键自动提交行为。

- [ ] **T06 — G0：软件真实双会话验收**（你＋软件；依赖：T05）
  - 动作：同窗口双终端、不同窗口分别连续轮换 20 次；覆盖浏览器前台、最小化、重名与会话退出。用真实权限提示验证显示、选择、回跳、处理和清除；记录失败与人工点击。
  - 交付：逐次 CSV／报告和屏幕录制索引，版本及计时起止定义。
  - 验收：两组各至少 18/20 自动成功，零错跳、零误提交；自动成功样本 P95 ≤1 秒，失败／人工兜底另列。任何一项未达标不通过 G0，不下完整载板订单。

### 模块与固件

- [ ] **T07 — 取得免焊台架与正式接线表**（硬件＋你；依赖：T02、T06）
  - 动作：确认购买预焊 Pico 2、指定 SPI 模组及按钮；硬件方核对模组说明书、供电、GPIO 和共地，接好并固定，标记线束，提供实拍与首通电检查。你只插 USB 和已标记连接器。
  - 交付：实物、SKU／版本、物理脚号到 GPIO 的接线表、首次点亮记录。
  - 验收：无裸 FPC／待焊排针留给你；不存在未确认的 5V GPIO 信号；若替料先回到选型复核。

- [ ] **T08 — 冻结一期协议 v1 与测试向量**（软件／固件；依赖：T05）
  - 动作：定义 HELLO、STATE_SNAPSHOT、STATE_APPLIED、INPUT_EVENT、ACTION_RESULT、HEARTBEAT 的字节布局、长度上限、端序、报告 ID、分片、超时、序号、连接代次和能力；拒绝不兼容主版本。
  - 交付：协议文档与同一组 C／C# 编解码测试向量，重复／截断／超长／旧版本用例。
  - 验收：快照版本与会话映射一致，动作去重、跨重连不重放；PC 与固件对样本得到一致结果。USB 报告大小按实际描述符定，不能凭假设写死。

- [ ] **T09 — USB 复合设备与基础输入**（固件；依赖：T01、T07、T08）
  - 动作：实现标准键盘 HID＋独立厂商通道、序列号、按钮去抖与释放、主循环调度；保留 BOOTSEL／SWD 恢复路径。记录开发 VID/PID 来源及限制。
  - 交付：UF2、构建记录、烧录／恢复图文、Windows 枚举记录。
  - 验收：基础键盘无需专用内核驱动，上位机能区分自己的厂商通道；按下／松开匹配；刷错应用后仍可恢复。此时只验台架按钮，不声称 21 键通过。

- [ ] **T10 — 显示驱动与可操作快照**（固件；依赖：T07、T08、T09）
  - 动作：驱动准确版本 ST7789，确认偏移／旋转／颜色；局刷状态卡、中文固定字与短名。切换期间进入不可操作态，完整绘制后发布映射并确认应用。
  - 交付：显示示例、RAM／Flash 占用、局刷与输入并发记录。
  - 验收：纯色、文字、边缘无错位；旧包不覆盖新卡；刷新中按键不会出现“看 A 跳 B”；屏刷不能长期阻塞按键扫描。

- [ ] **T11 — 上位机接入真实 HID 设备**（软件；依赖：T08–T10）
  - 动作：实现设备发现、握手、状态下发、应用确认、按键上行、心跳、断线恢复；将模拟传输替换为设备适配器，共用队列。
  - 交付：实机协议日志和双会话运行录像。
  - 验收：按键只执行对应已显示且仍有效的快照；版本不符反馈刷新；拔插恢复最新状态，旧按键不能重新执行。

- [ ] **T12 — 完整键位与离线行为定义**（软件／固件；依赖：T08）
  - 动作：提交 21 键、旋钮和五向开关映射表，编码／数字／创意层及切层提示；实现有限配置持久化、版本检查与坏配置恢复。未实现的语音／片段库键显示“未启用”，不伪装可用；创意层可用明确的标准快捷键预设。
  - 交付：`keymap` 定义和配置格式、各按键的 HID 或应用动作责任表；大键至少支持默认回跳与一个标准快捷键改绑。
  - 最小设备菜单：五向开关上下移动菜单项、左右调整选项、中心确认设备设置，只包含亮度和当前层；旋钮浏览待办、按压回队首。菜单不能批准 Agent 操作，菜单打开时屏上明确提示、大键暂停回跳；关闭后先恢复完整状态卡再启用。
  - 验收：通用基础键在上位机退出后可用；依赖会话的功能显示离线；复制不在无选区终端发 Ctrl+C；未知上下文禁用智能复制并提示。后续整机逐键实测。

- [ ] **T13 — G1：有线台架闭环与压力验收**（你＋软件；依赖：T11、T12）
  - 动作：按 T06 的两组场景用实体按钮重跑；局刷同时操作至少 200 次，拔插 20 次；测试主机睡眠与应用重启。用录屏／相机或统一时钟核对实机上屏时延。
  - 交付：输入事件计数、失败明细、视频、跳转与上屏原始耗时。
  - 验收：零丢键、零重复、零错跳、零误提交；回跳保持两组各≥18/20、P95≤1 秒；真实状态到显示的成功样本 P95≤2 秒，超时／失败单列，不能排除后不报。普通权限通知延迟路径单列，不冒充实时达标。失败先修模块，暂不开板。

### 完整硬件交付

  - 交付：STEP／结构源文件／STL、尺寸与干涉检查、外观确认记录。

  - 交付：正式固件、更新的接线图、逐键日志、电流及温升观察记录。

## 6. 验收计量与失败处理

- 每个样本记录场景、预期会话、实际会话、屏幕快照版本、触发时间、结果、耗时、是否人工协助；不得只报一个 PASS。
- 上屏耗时从可观察的真实 Agent 状态变化开始，到实机完整显示可操作卡片结束。仅从 Hook 到达开始计时只能叫软件传输耗时。录像与设备日志交叉核对，不直接相减未同步的主机／MCU 时钟。
- 回跳从实体按下到正确窗口及终端可见且焦点核实；手动点击兜底不计入自动成功。P95 使用最近秩法 `sorted[ceil(0.95*n)-1]`，报告有效 n、总 n、超时、失败和最大值。
- 在 G0/G1/G2 前预先固定试验场景，不能为达标移除失败场景。修复后重跑受影响组，保留原失败记录。
- 硬件未到货只允许勾选软件／设计任务；模拟与真实样机不得互替。供应商测试未覆盖 Windows 会话时不能代替 T22。
- T24 完成代表一期可用且可恢复，不代表三模、售价、量产可靠性或商业需求已验证。
- 日志默认只包含设备编号、短期会话标识、事件类型、版本和耗时；不保存原始 Hook JSON、提示词、完整路径、终端内容或凭证。视频可能包含私人代码，存放位置与提交范围由你确认，Git 中优先放脱敏证据索引。
